# WHA Workforce

แอปกลางบริหารพนักงานคลังสินค้า WHA (คลัง 5, คลัง 32, คลัง 29, คลัง Ecommerce) ใช้ได้ทั้งมือถือและคอม
สร้างใหม่แทนแอปเดิมที่ทำด้วย Lovable ทีละโมดูล

## บทบาท

| บทบาท | ทำอะไรได้ |
|---|---|
| พนักงาน | ดู/แก้ข้อมูลติดต่อของตัวเอง เปลี่ยนรหัสผ่าน ดูตารางกะของตัวเองและเพื่อนร่วมคลัง (เดือนที่ประกาศแล้ว) ลงเวลา ยื่นใบลา ขอแก้เวลา |
| หัวหน้างาน | เห็นพนักงานในคลังที่ดูแล วางกะ/ประกาศตารางกะ ติดตามการเข้างาน อนุมัติแก้เวลา อนุมัติลาขั้น 1 |
| แอดมินคลัง | จัดการพนักงานในคลังที่ได้รับมอบหมาย ตั้งบทบาทได้ถึงหัวหน้างาน รีเซ็ตรหัสผ่าน แก้ตัวเลือกตั้งค่า |
| ผู้บริหาร | ทำได้เหมือนแอดมินแต่ทุกคลัง ตั้งบทบาทได้ถึงแอดมินคลัง อนุมัติลาขั้น 2 (ลาตั้งแต่ N วัน) แก้กฎลงเวลา/ลา |
| ผู้ดูแลระบบสูงสุด | ทุกอย่าง รวมถึงเพิ่ม/แก้คลังและตั้งผู้บริหาร |

สิทธิ์ทั้งหมดตรวจในฐานข้อมูล (Row Level Security) ถึงเลี่ยงหน้าจอก็ทำเกินสิทธิ์ไม่ได้ (`npm test` ตรวจให้)

## การเข้าใช้ครั้งแรก

1. เข้าด้วยรหัสพนักงาน + รหัสผ่านเริ่มต้น (แจ้งโดยแอดมิน ไม่แสดงบนหน้าเว็บ)
2. ระบบบังคับตั้งรหัสผ่านใหม่ทันที: อย่างน้อย 8 ตัว ไม่ใช้เลขเรียง ไม่มีรหัสพนักงานอยู่ในรหัส
3. ลืมรหัส: แอดมินกด "รีเซ็ตรหัส" ในหน้าผู้ใช้และสิทธิ์ แล้วเจ้าของบัญชีเข้าด้วยรหัสเริ่มต้นและตั้งใหม่

## ติดตั้ง (ครั้งแรก)

1. สร้างโปรเจกต์ Supabase (Region: Singapore) ด้วยบัญชี GitHub `pcgwarehouse5-pixel`
2. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า (พิมพ์เองในเครื่อง ห้ามส่งในแชท)
3. สร้างตาราง: `npm run db:setup`
4. สร้างผู้ดูแลระบบสูงสุดคนแรก: `npm run create-admin`
5. Supabase > Authentication > Sign In / Providers: ปิด "Allow new users to sign up" (สร้างบัญชีผ่านแอปเท่านั้น)
6. Vercel: ใส่ `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `DEFAULT_USER_PASSWORD`, `NEXT_PUBLIC_LOGIN_DOMAIN`

## คำสั่งที่ใช้บ่อย

- `npm run dev` เปิดในเครื่องที่ http://localhost:3000
  - ดูหน้าจอโดยไม่ต้องล็อกอิน (เฉพาะในเครื่อง): ต่อท้าย `?preview=admin` (หรือ employee / supervisor / executive / super_admin) ปิดด้วย `?preview=off`
- `npm test` ทดสอบสิทธิ์ทุกบทบาทบน Postgres จำลอง (ไม่แตะข้อมูลจริง)
- `npm run db:check` ตรวจการเชื่อมต่อ Supabase / `npm run db:security` ตรวจ RLS และสิทธิ์บนฐานข้อมูลจริง (อ่านอย่างเดียว)
- `node scripts/backup-db.mjs` สำรองทุกตารางเป็น JSON ในโฟลเดอร์ `backups/` (ทำก่อนแก้โครงสร้างฐานข้อมูลทุกครั้ง ไม่ขึ้น GitHub)
- `node scripts/e2e-temp.mjs create` / `passwords` / `delete` สร้าง/ตั้งรหัสสุ่ม/ลบ คลัง ZZTEST และบัญชีทดสอบ ztest-* ชั่วคราว สำหรับทดสอบระบบจริง
- `node scripts/e2e-shifts.mjs` / `node scripts/e2e-attendance.mjs` / `node scripts/e2e-ot.mjs` ทดสอบตารางกะ / ลงเวลา+ลา กับฐานข้อมูลจริงด้วยบัญชีทดสอบ (แตะเฉพาะคลัง ZZTEST)
- `npm run typecheck` / `npm run lint` / `npm run build` ตรวจก่อน push

## ย้ายข้อมูลจากแอปเดิม (ทำซ้ำได้)

1. ในแอปเดิม (Lovable) เข้า `/admin/export` ดาวน์โหลด Zip แล้วแตกไว้ที่ `lovable-data/export-YYYYMMDD-HHMM/`
2. ซ้อม (อ่านอย่างเดียว): `node scripts/import-lovable.mjs` แล้วตรวจสรุปจำนวนและรายการที่ชนกัน
3. นำเข้าจริง: `node scripts/import-lovable.mjs --apply`
   - คนใหม่: สร้างบัญชีด้วยรหัสเริ่มต้น และต้องตั้งรหัสใหม่ตอนเข้าครั้งแรก
   - คนที่มีแล้ว: อัปเดตข้อมูลตามแอปเดิม แต่ไม่แตะบทบาท รหัสผ่าน และสถานะการตั้งรหัส
   - คนลาออก: ปิดการล็อกอิน
   - ตารางกะ: เพิ่มเฉพาะวันที่ยังไม่มีในแอปใหม่ (ไม่ทับที่แก้แล้ว) และตั้งเดือนเดิมเป็น "ประกาศแล้ว"
   - นำเข้าเฉพาะตารางกะ (ไม่แตะข้อมูลพนักงานที่แก้ในแอปแล้ว): `node scripts/import-lovable.mjs --apply --shifts-only`
4. ตรวจผล: `node scripts/check-import.mjs` (จำนวนแยกคลัง/บทบาท และจำลองสิทธิ์ของแต่ละบทบาท)

## สำรองข้อมูล

แพ็กเกจฟรีของ Supabase ไม่สำรองข้อมูลอัตโนมัติ ควรสำรองอย่างน้อยสัปดาห์ละครั้ง:

```bash
npx supabase db dump --db-url "$SUPABASE_DB_URL" --data-only -f backup.sql
```

## ข้อมูลจากแอปเดิม

โฟลเดอร์ `lovable-data/` และ `lovable-source/` เป็นข้อมูลจริงของพนักงาน (PDPA) ใช้ในเครื่องเท่านั้น ไม่ขึ้น GitHub
